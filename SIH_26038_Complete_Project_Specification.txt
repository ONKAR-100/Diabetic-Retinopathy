======================================================================
1. SIH PROBLEM STATEMENT
======================================================================

Problem Statement ID: SIH 26038

Build an automated diabetic retinopathy (DR) screening and telemedicine
workflow combining image quality assessment/enhancement, retinal
structure and lesion analysis, DR severity grading, explainability,
human-in-the-loop ophthalmologist validation, automated reporting, and
Simulink-based workflow/resource simulation.

The intended DR grading follows the International Clinical DR Severity
Scale:

Level 0 - No DR
Level 1 - Mild NPDR
Level 2 - Moderate NPDR
Level 3 - Severe NPDR
Level 4 - Proliferative DR

Referable DR = Level 2 or higher.

2. SIH REQUIREMENTS
======================================================================

REQUIREMENT 1 - IMAGE QUALITY ASSESSMENT AND ENHANCEMENT
- Assess focus/sharpness, illumination/brightness and field of view.
- Identify good, borderline and ungradable images.
- Apply adaptive enhancement to borderline images.
- Use CLAHE, illumination normalization and denoising where required.
- Reject images that remain ungradeable.
- Give recapture feedback explaining the rejection reason.

Current status:

Frontend/backend integration must expose clear recapture feedback.

REQUIREMENT 2 - RETINAL STRUCTURE AND LESION ANALYSIS

- Fovea localization.
- Retinal vessel segmentation/extraction.
- Microaneurysm detection/segmentation.
- Exudate segmentation.
- Hemorrhage classification/detection.
- Neovascularization detection.

Current status:
Vessel extraction model: READY.
Fovea localization: READY / BEING INTEGRATED.
Lesion analysis: PLANNED FOR LATER.
Optic disc functionality must be confirmed/added if not already available.

REQUIREMENT 3 - DR SEVERITY GRADING
- Five-class Level 0-4 grading.
- Referable DR defined as Level 2+.
- Target sensitivity >90% for referable DR.
- Target specificity >85% for referable DR.
- Validate using held-out evaluation data.

Current status:
EfficientNet-B2 DR grading model is READY.
Referable threshold logic exists.
Performance targets must be demonstrated before being claimed.

REQUIREMENT 4 - EXPLAINABILITY
- Grad-CAM attention maps.
- Lesion-level evidence correlated with clinical criteria.
- Calibrated confidence scores.
- Automated annotated reports.
- Ophthalmologist validation in a human-in-the-loop workflow.
- Target validation/review time under 30 seconds.

Current status:
Grad-CAM is READY.
Grad-CAM is model explainability, NOT lesion segmentation.
Lesion-level evidence requires dedicated lesion models.
Confidence calibration, report integration and measured usability
validation still need to be completed.

REQUIREMENT 5 - SIMULINK TELEMEDICINE WORKFLOW
Model:
- Image/patient acquisition rates.
- Network bandwidth.
- Processing throughput.
- Review capacity.
- Queues and delays.
- Resource utilization.
- District-level scaling.

Demonstrate a workflow capable of serving 100,000+ patients/year.

The AI does NOT need to be rewritten in MATLAB. Python/PyTorch can remain
the AI layer while MATLAB/Simulink models the system-level workflow.

5. IMAGE QUALITY AND ENHANCEMENT
======================================================================

Quality engine evaluates:
- Brightness/illumination.
- Contrast.
- Focus/sharpness.
- Field of view.
- Overall quality.

Typical workflow:
GOOD -> continue.
BORDERLINE -> enhance -> reassess -> continue/reject.
UNGRADABLE -> stop AI -> explain reason -> request recapture.

Possible recapture messages:
- Image too dark.
- Image overexposed.
- Insufficient field of view.
- Image not sufficiently focused.
- Retinal region not adequately visible.

Enhancement pipeline can include:
Original -> retinal ROI -> illumination correction ->
LAB CLAHE -> denoising if needed -> resize/normalization ->
enhanced image -> quality reassessment.

6. DR GRADING
======================================================================

Current model:
EfficientNet-B2 five-class classifier.

Outputs:
Grade 0 - No DR
Grade 1 - Mild NPDR
Grade 2 - Moderate NPDR
Grade 3 - Severe NPDR
Grade 4 - Proliferative DR

The result page should show:
- Predicted grade.
- Grade description.
- Class probabilities.
- Confidence.
- Referable status.

Referable rule:
Grade 0-1 = Non-referable.
Grade 2-4 = Referable.

Five-class prediction and binary referable decision should be displayed
as separate pieces of information.

10. GRAD-CAM
======================================================================

Grad-CAM answers:
"Which regions contributed most strongly to the classifier's prediction?"

Process:
Fundus -> DR classifier -> selected class ->
late convolutional feature maps -> class gradients ->
weighted activation map -> resize -> heatmap -> overlay.

Show:
1. Original fundus.
2. Grad-CAM heatmap.
3. Original + Grad-CAM overlay.

IMPORTANT:
Grad-CAM does not inherently identify a lesion type and does not give
precise lesion boundaries.

Grad-CAM = where the classifier's decision was influenced.
Segmentation mask = which pixels belong to a structure/lesion.
Lesion mask = pixel/region evidence for a particular lesion.

13. CALIBRATED CONFIDENCE
======================================================================

Raw softmax probability is not automatically calibrated confidence.

Planned:
Raw model probability -> calibration method (e.g. temperature scaling)
-> calibrated confidence -> UI/report.

Validate with:
- Expected Calibration Error (ECE).
- Reliability diagram.
- Brier score.

25. 100,000+ PATIENT/YEAR CAPACITY
======================================================================

The requirement means demonstrating system capacity through simulation;
it does not require 100,000 real patient images.

Illustrative workload:
100,000 patients/year is approximately 274 patients/day.
At 10 operating hours/day, this is approximately 27 patients/hour.

These are example simulation assumptions, not measured deployment
values.

The simulation should test different resource configurations and find
the bottleneck and required resources.

Example:
1 GPU + 1 ophthalmologist
2 GPUs + 2 ophthalmologists
5 GPUs + 5 ophthalmologists
10 GPUs + 10 ophthalmologists

Compare:
- Throughput.
- Queue length.
- Waiting time.
- GPU utilization.
- Doctor utilization.
- Bandwidth utilization.
- Annual capacity.
